# 地震台网事件编目与复核台

值班组用来录台站与震相、编事件、看震级与定位残差、走复核与发布的小台子。

## 运行

```
npm install
npm start
```

默认端口 5225（`PORT` 可以覆盖），数据存在 `data/db.json`，页面在 `/`。

## 页面

- **概览**：台站数与运行中台站、事件数与各状态条数、震相与复核与发布条数、最大与平均震级、满足自动发布条件的待复核事件数、超过复核容差的复核条数、重复发布过的事件数。
- **台站**：台站台账（代码、名称、区域、经纬度、仪器、状态）与各台的震相条数、人工与自动条数；台站的增改删。
- **事件**：事件清单（编号、发震时刻、经纬度、深度、震级、台站数、残差、状态、复核/发布/更正次数）；按模板条件查看自动发布判定；逐条的复核、发布与发布后更正（含对外口径时间线）。
- **震相**：震相清单（台站、相位、到时、振幅、走时残差、拾取方式与质量），支持单条新增、批量导入与删除。
- **复核与发布**：复核记录、发布记录（含发布时位置快照）与更正台账（批次、更正人、依据、受影响事件与逐事件改前改后对照），支持单事件与批量更正登记。

## 口径（这一版按下列规则实现，页面上的说明与数字都要与本段一致）

1. **单台震级**：`lg(A) + 1.11 × lg(R) + 0.00189 × R − 2.09`，A 是振幅（微米），R 是震中距（公里）；**事件震级取各台站单台震级的中位数**，并给出参与台站数。
2. **震中距**：按球面距离算（两点经纬度，地球半径 6371 公里）。
3. **走时残差**：事件的残差是各条震相残差的均方根；**没有任何震相记录的事件不能自动发布**，只能走人工。
4. **自动发布条件**：震级不低于 `autoPublishMagnitude`（默认 4.0）、参与台站不少于 `minStationCount`（默认 4 个）、走时残差不大于 `rmsLimitSec`（默认 3.0 秒）、震源深度不超过 `shallowDepthLimitKm`（默认 70 公里，只自动发布浅源事件）。四条同时满足才自动发布。
5. **复核容差**：震级改动**超过** `reviewToleranceMagnitude`（默认 0.3）才需要上级确认；正好等于容差不算超。
6. **震相导入**：按「台站 + 相位 + 到时」去重，已经有的重复记录要跳过并在结果里报出跳过条数。
7. **台站代码**：大小写与首尾空格不敏感，同一个台站只能算一个台站。
8. **事件清单排序**：按震级从大到小，震级相同时按发震时刻从新到旧。
9. **最新复核**：一条事件的「最新复核」按复核时刻取，不是按录入先后。
10. **同一事件只能有一条有效发布**；重复发布要拦下并提示已经发布过。
11. **发布后的更正**：速报发出去之后改震级或位置（纬度、经度、深度、发震时刻）只能登记更正，不能直接改事件或借复核改。每次更正记录更正时刻、更正人、依据、受影响事件的改前/改后；登记后事件**当前对外口径值立即更新**（震级以发布/更正确定的值为准，台站测算值另行保留参考），**历史发布记录原样保留**（发布时快照震级与位置），事件详情里能看到「第一次发的是多少、第几次改成了多少」的时间线，事件清单与详情摆出发布次数、更正次数。一次更正影响多个事件（如同一批台站定标后统一调整）走批量登记，一次落账并返回受影响事件清单与逐事件差异；任一行校验不通过则整批不落账。

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | /api/health、/api/summary、/api/settings | 健康检查、概览、全局设置（PATCH 可改） |
| GET / POST | /api/stations | 台站清单 / 新增 |
| GET / PATCH / DELETE | /api/stations/:id | 台站详情（含该台震相）/ 修改 / 删除 |
| GET / POST | /api/events | 事件清单（支持 status、minMagnitude、regionName、from、to）/ 新增 |
| GET / PATCH / DELETE | /api/events/:id | 事件详情（含震相、复核、发布、自动发布判定）/ 修改 / 删除（已发布要带 force 与理由） |
| POST | /api/events/:id/reviews | 登记复核（可改震级与深度；已发布事件的口径改动会被拦下，要走更正） |
| POST | /api/events/:id/publish | 发布（`auto: true` 表示走自动发布，不满足条件会被拦下；发布时快照震级与位置） |
| POST | /api/events/:id/corrections | 登记一次发布后更正（`corrector`、`reason` 必填，`magnitude/lat/lon/depth` 填哪项改哪项） |
| POST | /api/corrections | 批量登记更正，body `{at?, corrector, reason, remark?, items:[{eventId, magnitude?, lat?, lon?, depth?}]}`，返回批次与 `affectedEvents` 逐事件差异 |
| GET | /api/corrections | 更正台账（支持 eventId、corrector） |
| GET | /api/events/:id/auto-check | 单独看这个事件的自动发布判定 |
| GET | /api/reviews、/api/publishes | 复核台账（支持 eventId、reviewer、overTolerance）/ 发布台账（支持 eventId、type） |
| GET / POST | /api/arrivals | 震相清单（支持 eventId、stationId、phaseType、pickType、from、to）/ 单条新增 |
| POST | /api/arrivals/import | 批量导入，body `{eventId, rows:[...], picker}` |
| DELETE | /api/arrivals/:id | 删除一条震相 |

出错的返回统一是 `{"error":{"code":"...","message":"...","details":{...}}}`，`details` 里会点名是哪个字段没过。
